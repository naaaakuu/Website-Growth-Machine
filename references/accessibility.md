# Accessibility

Load for any customer-facing change and for accessibility audit, remediation, or release decisions.

## Coverage model

Use automated checks to find detectable issues, then perform agreed manual coverage. Test representative templates, states, and user journeys across the browser/viewport matrix. Include keyboard-only navigation, visible focus, landmarks/headings, accessible names and labels, instructions/errors, contrast, zoom/reflow, reduced motion, dialogs, menus, dynamic announcements, and relevant screen-reader behavior.

Test actual interactions: menu, consent controls, search/filter, dialogs, tabs/accordions, forms, checkout/booking, errors, and confirmation. A visual screenshot or automated score does not prove keyboard or assistive-technology access.

## Remediation

Describe the user barrier, affected route/state, standard/design intent, reproduction, proposed change, automated/manual acceptance test, regression risk, and owner. Prioritize inaccessible core journeys and data/error handling above cosmetic conformance.

Do not exclude difficult pages or hide findings to improve a report. Automated tools cover only a subset of accessibility needs; do not present an automated pass as certification or jurisdiction-wide legal compliance. Seek appropriate specialist/legal review where the project requires it.
