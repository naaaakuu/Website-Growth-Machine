# How to Use Website Growth Engine

Use the package from a repository or attach the files to a capable agent. Give the agent only the facts, access, and authority it actually has. It should never infer production permission from a request to analyze or improve a site.

## New website

“Read website-growth-engine/SKILL.md. Use DISCOVER mode for [audience, market, offer]. Decide whether this deserves a new site, a section of an existing site, an original tool, or no build. Our desired outcome is [outcome and denominator]. We have [available data/tools]. Save an opportunity map and the smallest defensible build scope. Do not fabricate demand or deploy.”

## Existing website

“Read website-growth-engine/SKILL.md. Use IMPROVE mode for [site]. Our primary outcome is [outcome]. First inspect .growth records, protect valuable URLs and customer journeys, and establish baseline evidence. Diagnose the present bottleneck, make only authorized reversible improvements, test them, and record evidence. Do not deploy or materially alter URLs/indexing without approval.”

## Ranking or traffic decline

“Use RECOVER mode for [site] and the observed decline period. Compare acquisition, indexing, technical, demand, offer, analytics, and operational evidence before naming a cause. Protect valuable assets and prioritize active breakage. Record hypotheses, expected observable changes, tests, rollback, and what remains unknown.”

## CRO improvement

“Use AUDIT then EXPERIMENT mode for [journey]. Optimize [qualified outcome and denominator], with guardrails for [quality, margin, refunds, accessibility, speed]. Inspect the task, offer clarity, pricing, form/checkout errors, mobile states, and follow-up. Propose a mechanism-backed, instrumented intervention; do not use dark patterns or call a before/after change causal proof.”

## Technical audit

“Use AUDIT mode for [URL/repository]. Run the bounded site audit if authorized, then inspect representative routes, rendering, robots, canonicals, sitemap, links, structured-data rationale, core journeys, performance, accessibility, measurement, and reliability. Produce CRITICAL/HIGH/MEDIUM/LOW issues using the audit template. Do not claim site-wide coverage beyond tested scope.”

## Supporting-domain evaluation

“Use DISCOVER mode and read domain-portfolio. Evaluate [domain] for BUILD, CONSOLIDATE, REDIRECT, HOLD, SELL, RETIRE, or DEFER. Assess independent user value, audience overlap, distribution, maintenance cost, history/trademark risk, brand fit, and measurement complexity. Reject a doorway or backlink-network rationale.”

## Post-launch improvement

“Use MEASURE mode for [release/change]. Read the release report, .growth state, and authorized acquisition, conversion, CRM/order, performance, and incident evidence. Separate implementation, testing, observations, estimates, and hypotheses. Identify the current bottleneck and propose the next highest-value reversible intervention or properly designed experiment.”

## Installation and handoff

Keep one canonical directory. Merge the appropriate fragment into existing project instructions rather than replacing them. At every handoff, update .growth/state.json with current mode, completed/invalidated gates, evidence locations, blocker, owner, and next safe action.
